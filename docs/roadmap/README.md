# Повний шлях навчання: розробка застосунків на LLM

Цей шлях розрахований на розробників, які вже вміють програмувати і переходять у розробку застосунків на LLM або в AI-бекенд. Шість етапів радимо проходити послідовно; якщо відповідний досвід уже є — заходьте одразу в потрібну тему.

| Етап | Головна мета | Вхід | Ознака завершення |
|---|---|---|---|
| 0. Загальна картина | Розібратися в позиціях, термінах і технологічному ландшафті | [Шлях для початківця](beginner.md) | Можете пояснити межу між розробкою застосунків, ML-позиціями та звичайним бекендом |
| 1. Виклик моделі | Надійно вбудувати модель у бізнес-логіку | [Розробка застосунків](application.md) | Готовий застосунок зі стримінгом, структурованим виводом і обліком вартості |
| 2. RAG | Побудувати базу знань, яку можна виміряти | [Тема: RAG](../topics/rag.md) | Є гібридний пошук, цитування джерел і офлайн-набір для оцінювання |
| 3. Агенти | Опанувати інструменти, стан, планування та відновлення | [Шлях агента](agent.md) | Агент піддається трасуванню, зупинці та оцінюванню |
| 4. Продакшн-інженерія | Закрити деплой, продуктивність і надійність | [Тема: деплой](../topics/deployment.md) | Є навантажувальні тести, розрахунок потужностей і план реакції на збої |
| 5. Принципи та співбесіда | Зрозуміти Transformer і сформулювати відповіді | [Шлях до співбесіди](interview.md) | Можете пояснити принципи, компроміси у проєкті та метрики |

## Рекомендований порядок практики

1. Мінімальний AI-застосунок: стримінг, структурована відповідь, обробка помилок, облік вартості в токенах.
2. Питання-відповіді по базі знань: чанкінг документів, гібридний пошук, rerank, цитування, оцінювання та розбір помилок.
3. Агент з інструментами: межі дозволів, checkpoint, trace, відновлення після збоїв і набір для оцінювання.
4. Переведення в продакшн: шлюз, обмеження частоти запитів, таймаути, повторні спроби, моніторинг, поетапне викочування та звіт про потужності.
