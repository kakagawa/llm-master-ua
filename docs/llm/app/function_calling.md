# Function Calling: як модель викликає інструменти і чому це фундамент агентів

Якщо ви збираєтеся на співбесіду на позицію розробника агентів, то щонайменше маєте знати: що таке Function Calling і чому це передумова для агента?

## 1. Що таке Tool / Function?

У контексті застосунків на великих моделях **інструмент (tool)** чи **функція (function)** — це по суті **наперед описана логіка в коді**. Сама модель її не виконує, а **повідомляє застосунку, який саме код треба виконати**.

Function Calling — це і є виклик зовнішньої функції.

Ми знаємо, що велику модель навчають на величезному, але статичному наборі даних. Її знання, можливості й точність обмежені. Наприклад, коли DeepSeek R1 вийшла у 2025 році, її навчальні дані були обмежені груднем 2023 року. Тож, судячи з самих лише даних, навіть найрозумніша модель не знатиме, що сталося пізніше.

Function Calling додає цьому розумному «мозку» «руки» й «ноги», щоб він міг взаємодіяти із зовнішнім світом і долати ці обмеження.

## 2. Чим це відрізняється від звичайних питань-відповідей?

Різниця принципова. Якщо коротко: звичайні питання-відповіді — це «говорити», а Function Calling — це «робити».

| Вимір | Звичайні питання-відповіді (Chat Completion) | Function Calling (Tool Use) |
| :----------- | :-------------------------- | :------------------------------------------------- |
| **Що на виході** | чистий текст природною мовою | **структуровані дані** (JSON / об'єкт) із явною назвою функції та параметрами |
| **Джерело знань** | лише навчальні дані (до дати відсікання) | **зовнішні дані в реальному часі** (через інструмент) |
| **Точність** | легко галюцинує (вигадує дані) | **висока достовірність** (на основі реальної відповіді API) |
| **Виконання дій** | не може виконувати дії, лише «говорить» | може **запускати дії** (оформити замовлення, надіслати листа, зробити запит до бази) |
| **Керованість** | формат виводу важко жорстко обмежити | формат виводу **суворо відповідає JSON**, зручно розбирати програмно |
| **Типові сценарії** | розмови, написання текстів, переклад, реферування | запити актуальної інформації, робота з бізнес-системами, планування багатокрокових задач |

## 3. Що насправді відбувається, коли модель «викликає інструмент»?

Процес Function Calling умовно ділиться на 4 кроки:

![Процес роботи Function Calling](https://file1.kamacoder.com/i/web/20260512163402_fc01.png)

**Крок 1: розробник описує й надає інструменти (functions)**

На самому початку треба повідомити моделі, які «інструменти» їй доступні. Це наче дати помічникові ящик з інструментами й пояснити призначення кожного.

**Крок 2: модель відповідає вказівкою на виклик функції**

Коли користувач ставить запит (наприклад: «яка зараз температура в Києві?»), ваш застосунок надсилає моделі і питання користувача, і перелік інструментів. Обробивши запит, модель визначає, що для отримання інформації потрібен зовнішній інструмент. Її відповіддю буде не звичайний текст, а структуровані параметри виклику функції.

**Крок 3: застосунок виконує функцію й знову звертається до моделі**

Це найважливіший крок усього процесу. Отримавши відповідь моделі, код вашого застосунку має перевірити її, розібрати вказівку, виконати функцію й знову звернутися до моделі.

**Останній крок:** отримавши всю цю інформацію, модель використовує результат виконання функції та формує природну підсумкову відповідь користувачеві: «Сьогодні в Києві ясно, температура 25 градусів».

### Розбір процесу на цьому прикладі

1. **Розпізнавання наміру й витягування параметрів.** У першому раунді модель не відповідає про погоду, а видає **структуровані дані (зазвичай JSON)**, які кажуть: «мені треба викликати функцію `get_current_weather`, параметр `location` — `Київ`».
2. **Передавання керування.** Ініціатива повертається до вашого коду. Програма розбирає цей JSON, бачить, що треба викликати `get_current_weather`, і виконує її у вашому серверному середовищі.
3. **Повернення результату.** Ви надсилаєте моделі реальний результат виконання функції (`{"temp": 25, "condition":"ясно"}`) знову ж таки у форматі JSON.
4. **Підсумковий синтез.** Побачивши результат, модель разом із контекстом формулює остаточну відповідь природною мовою.

## 4. Чому Function Calling є фундаментом агентів?

Якщо велика модель — це «мозок», то Function Calling — «нервова система», яка з'єднує мозок із руками й ногами (інструментами). Без неї агент лишається тим, хто вміє лише говорити, але не діяти.

### 1. Від «пасивної відповіді» до «активної дії»

Без Function Calling: ви питаєте «як забронювати переговорну?» — і отримуєте статтю «Посібник з бронювання переговорних».

З Function Calling: ви кажете «забронюй мені переговорну A на завтра на 15:00» — і модель викликає задану розробником функцію `book_room(time="15:00", room="A")`, справді виконує бронювання й повертає номер заявки.

Це і є якісний стрибок, з якого народжується агент — сутність, здатна сприймати середовище й діяти для досягнення мети.

### 2. Передумова планування складних задач (патерн ReAct)

Просунутому агенту часто потрібне багатокрокове міркування (Plan & Solve). Наприклад: «проаналізуй дані продажів за минулий місяць і, якщо вони нижчі за план, надішли листа менеджеру з продажів». Тут модель має вміти будувати ланцюжок викликів, послідовно й точно **обираючи інструмент** і **витягуючи параметри**:

1. Спершу викликати `query_sales_data(month="last")`.
2. **Зробити логічний висновок за отриманим результатом** (внутрішнє міркування моделі).
3. Якщо умова виконується — викликати `send_email(to="manager", content=...)`.

Якщо Function Calling працює неточно, увесь ланцюжок розривається.

### 3. Дієвий спосіб розв'язати проблему галюцинацій та актуальності

Головна цінність агента — розв'язувати реальні задачі, а вони зазвичай пов'язані з приватними даними або станом у реальному часі.

Змусити модель запам'ятати всі залишки на складі через донавчання? Неможливо, дані змінюються щодня. Запхати мільйони рядків у промпт? Ні-ні: контекст обмежений і дорогий. А от через Function Calling модель за потреби робить точковий запит саме туди, куди треба. Це дає агенту «безмежну базу знань» і «сприйняття в реальному часі».

## 5. Як це можуть спитати на співбесіді

Готуючись до співбесіди, зверніть увагу на ці часті питання.

1. **«Опишіть коротко процес Function Calling».**

   Не обмежуйтеся фразою «модель викликає функцію». Наголосіть на послідовності: «модель видає структурований вивід (JSON) → програма перехоплює й виконує → результат повертається → модель формує підсумкову відповідь».

2. **«Що робити, якщо модель викликала не той інструмент або неправильно витягла параметри?»**

   Згадайте **механізм повторних спроб** (дати моделі переосмислити ситуацію за інформацією про помилку), **few-shot prompting** (навести в промпті приклади правильних викликів), а також **покращення описів інструментів** (чіткіше визначити параметри).

3. **«Чим Function Calling відрізняється від звичайної вказівки в промпті на кшталт "виклич API"?»**

   Наголосіть на **структурованому виводі** й **надійності**. За звичайної вказівки модель може вигадати сам процес виклику API, а Function Calling змушує її видати JSON, що відповідає схемі, і програма точно розбере й виконає його.

------

## 6. Підсумок

Function Calling — це **строгий інженерний протокол**. Він перетворює прикладну розробку з **«генерації тексту»** на **«виконання бізнес-дій»** і є безумовним фундаментом для побудови агентів.
